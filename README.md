# ค่าลูกขนไก่ - ชมรมแบดมินตัน

แอปสำหรับบันทึกการเล่นแบดมินตัน คำนวณค่าลูกขนไก่ต่อคน และติดตามยอดค้างชำระของแต่ละคน ไม่ต้องล็อกอิน ใช้ได้จากมือถือทุกเครื่อง

- **Frontend**: React + TypeScript + Vite
- **Database**: Google Sheets (เข้าถึงผ่าน Google Apps Script Web App — ไม่มี backend server แยกให้ดูแล)

## โครงสร้างโปรเจกต์

```
apps-script/   โค้ด Google Apps Script (นำไปวางใน Apps Script editor)
scripts/       สคริปต์ช่วยงาน (ทดสอบ backend)
public/        ไอคอนแอป + manifest
src/           โค้ด React
```

### ไอคอนแอป

ไฟล์ต้นฉบับคือ `public/logo-source.jpg` (768×768) ถ้าต้องการเปลี่ยนโลโก้ ให้แทนที่ไฟล์นี้แล้วสร้างไอคอนใหม่ด้วย `sips` (มีมากับ macOS):

```bash
SRC=public/logo-source.jpg
sips -s format png -Z 512 "$SRC" --out public/icon-512.png
sips -s format png -Z 192 "$SRC" --out public/icon-192.png
sips -s format png -Z 180 "$SRC" --out public/apple-touch-icon.png
sips -c 600 600 "$SRC" --out /tmp/crop.png
sips -s format png -Z 32 /tmp/crop.png --out public/favicon-32.png
sips -s format png -Z 16 /tmp/crop.png --out public/favicon-16.png
sips -s format png -Z 410 "$SRC" --out /tmp/inner.png
sips --padToHeightWidth 512 512 --padColor FFFFFF /tmp/inner.png --out public/icon-maskable-512.png
```

## ขั้นตอนที่ 1: สร้าง Google Sheet + Apps Script

1. สร้าง Google Sheet ใหม่ (เช่นตั้งชื่อ "AeroThai Badminton Club DB")
2. เปิด **Extensions → Apps Script** จากเมนูของ Sheet
3. ในหน้า Apps Script editor ให้สร้างไฟล์ `.gs` ตามชื่อในโฟลเดอร์ `apps-script/` ของโปรเจกต์นี้ (Code.gs, Utils.gs, Players.gs, Games.gs, Balances.gs, Settings.gs, Line.gs, LineFlex.gs) แล้วคัดลอกเนื้อหาแต่ละไฟล์ไปวาง
4. ในหน้า Apps Script editor เลือกฟังก์ชัน `setupSheets` จาก dropdown ด้านบน แล้วกด **Run** (ครั้งแรกจะขอสิทธิ์เข้าถึง Sheet ให้กด Authorize) — ฟังก์ชันนี้จะสร้างชีตทั้ง 4 แผ่น (`Players`, `Games`, `Settlements`, `Settings`) พร้อมหัวตารางและตั้งราคาลูกขนไก่เริ่มต้นที่ 10 บาท/ลูกให้อัตโนมัติ
5. ไปที่ **Deploy → New deployment**
   - Type: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
6. กด Deploy แล้วคัดลอก **Web app URL** ที่ได้ (ลงท้ายด้วย `/exec`) เก็บไว้ใช้ในขั้นตอนถัดไป

> หมายเหตุ: ทุกครั้งที่แก้ไขโค้ด `.gs` ต้องกด **Deploy → Manage deployments → แก้ไข (ไอคอนดินสอ) → New version → Deploy** เพื่อให้ URL เดิมใช้โค้ดล่าสุด

## ขั้นตอนที่ 2: ตั้งค่าฝั่ง React

```bash
npm install
cp .env.example .env.local
```

แก้ไข `.env.local` ให้ `VITE_APPS_SCRIPT_URL` เป็น URL ที่ได้จากขั้นตอนที่ 1:

```
VITE_APPS_SCRIPT_URL=https://script.google.com/macros/s/XXXXX/exec
```

## ขั้นตอนที่ 3: Deploy ขึ้น Vercel

### 3.1 ตรวจสอบ backend ก่อน

```bash
npm run check:backend "https://script.google.com/macros/s/XXXXX/exec"
```

ต้องขึ้น ✅ ครบทุกรายการก่อนไปขั้นตอนถัดไป ถ้าไม่ผ่านให้ดูหัวข้อ "แก้ปัญหาที่พบบ่อย" ด้านล่าง

### 3.2 push โค้ดขึ้น GitHub

```bash
git add -A && git commit -m "Badminton shuttle cost tracker" && git branch -M main
```

จากนั้นสร้าง repo บน GitHub แล้ว `git remote add origin <url>` และ `git push -u origin main`

> `.env.local` ถูก gitignore ไว้แล้ว จะไม่ถูก push ขึ้นไป

### 3.3 สร้างโปรเจกต์บน Vercel

1. ไปที่ [vercel.com/new](https://vercel.com/new) → Import repo ที่เพิ่ง push
2. Vercel จะตรวจเจอ Vite เองอัตโนมัติ (Build: `npm run build`, Output: `dist`) — ไม่ต้องแก้
3. กางหัวข้อ **Environment Variables** แล้วเพิ่ม:

   | Key | Value |
   |---|---|
   | `VITE_APPS_SCRIPT_URL` | URL `/exec` จากขั้นตอนที่ 1 |

   เลือกให้ครบทั้ง Production, Preview และ Development
4. กด **Deploy**

> ⚠️ **สำคัญ**: Vite ฝังค่า env ตอน build ไม่ใช่ตอนรัน ถ้าแก้ `VITE_APPS_SCRIPT_URL` ทีหลัง ต้องกด **Redeploy** ด้วย ไม่งั้นค่าเดิมจะยังติดอยู่ในไฟล์ที่ build ไว้

### 3.4 ทดสอบหลัง deploy

เปิดเว็บที่ได้จากมือถือ แล้วลองบันทึกเกม 1 เกม จากนั้นเปิด Google Sheet ดูว่ามีแถวเพิ่มในชีต `Games` และ `Players` จริง

## หมายเหตุเรื่องความเร็ว

การเรียก Apps Script แต่ละครั้งมี overhead คงที่ราว ~1 วินาที (redirect + cold start) ไม่ว่าจะดึงข้อมูลมากหรือน้อย ดังนั้น **จำนวนครั้งที่เรียก** สำคัญกว่าขนาดข้อมูล แอปนี้จึงออกแบบไว้ว่า:

- ใช้ action `bootstrap` ดึง settings + รายชื่อผู้เล่น + เกมของเดือนที่กำลังดู ในครั้งเดียว (เปิดแอป = 1 request)
- เมื่อบันทึก/แก้ไข/ลบเกม จะนำผลลัพธ์ที่ backend ส่งกลับมาใส่ในหน้าจอเลย ไม่ดึงข้อมูลใหม่ทั้งเดือน (บันทึกเกม = 1 request)
- เก็บข้อมูลล่าสุดไว้ใน `localStorage` เปิดแอปครั้งต่อไปจะเห็นข้อมูลทันที แล้วค่อยอัปเดตเบื้องหลัง (ขึ้นข้อความ “กำลังอัปเดต…”)

ถ้าแก้โครงสร้างข้อมูลที่ cache ไว้ ให้เพิ่มเลข `VERSION` ใน `src/lib/cache.ts` เพื่อทิ้ง cache เก่า

## แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| ได้ HTML กลับมาแทน JSON / เว็บโหลดข้อมูลไม่ขึ้น | deployment ตั้ง access ไม่เป็น **Anyone** — Google ส่งหน้า login มาแทน ไปที่ Deploy → Manage deployments → แก้เป็น Anyone |
| แก้โค้ด `.gs` แล้วเว็บยังทำงานแบบเดิม | ต้องกด Deploy → Manage deployments → ไอคอนดินสอ → Version: **New version** → Deploy (URL เดิมจะชี้ไปโค้ดใหม่) |
| `getRecentPayments_ is not defined` / `buildPaidHistoryFlex_ is not defined` | ไฟล์ `Line.gs` กับ `LineFlex.gs` ในโปรเจกต์ Apps Script ไม่ใช่เวอร์ชันเดียวกัน — คัดลอกใหม่ทั้งสองไฟล์ แล้ว **Deploy → Manage deployments → New version** |
| `ไม่พบชีต: Games` | ยังไม่ได้รัน `setupSheets` หรือชื่อแท็บถูกแก้ ต้องเป็น `Players`, `Games`, `Settlements`, `Settings` เป๊ะ ๆ |
| บันทึกเกมไม่ได้ แต่ดูข้อมูลได้ | มักเป็นปัญหา CORS ตอน POST — ตรวจว่า deploy เวอร์ชันล่าสุดแล้ว (โค้ดฝั่ง frontend ส่งเป็น `text/plain` เพื่อเลี่ยง preflight อยู่แล้ว) |
| องค์กรไม่ให้เลือก "Anyone" | ดูหัวข้อ "ข้อจำกัดของ Google Workspace" ด้านล่าง |

### ข้อจำกัดของ Google Workspace

ถ้าบัญชีเป็นของบริษัทและผู้ดูแลระบบปิดการแชร์แบบสาธารณะไว้ ตัวเลือก **Anyone** อาจไม่ขึ้นให้เลือก (เห็นแค่ "Anyone within [องค์กร]") ซึ่งจะทำให้แอปเรียก API ไม่ได้เพราะ Google จะ redirect ไปหน้า login แล้วติด CORS

ทางออก: deploy Apps Script จาก **บัญชี Gmail ส่วนตัว** (สร้าง Google Sheet ใหม่ในบัญชีนั้น แล้วรัน `setupSheets`) หรือขอให้ผู้ดูแลระบบอนุญาตเป็นกรณีไป

## ฟีเจอร์หลัก

- **บันทึกเกม (ปฏิทิน)** — แสดงเป็นปฏิทินรายเดือน วันนี้ไฮไลต์สีเข้มเห็นชัด และวันที่มีเกมจะแสดงจำนวนเกม
  - แตะวันที่บนปฏิทิน = ดู **ประวัติการเล่น** ของวันนั้นอย่างเดียว (พร้อมแก้ไข/ลบเกมได้)
  - กดปุ่ม **บันทึกเกม** = เปิดฟอร์มกรอกข้อมูล (ตั้งค่าเริ่มต้นเป็นวันนี้ และเปลี่ยนวันที่ในฟอร์มได้ เพื่อบันทึกย้อนหลัง)
  - ใส่ผู้เล่นได้ **1–4 คน** (กด “ลบ” เพื่อเอาช่องที่ไม่ใช้ออก หรือ “＋ เพิ่มผู้เล่น” เพื่อเพิ่ม) ค่าลูกขนไก่จะหารตามจำนวนช่องที่กรอกจริง เช่น เล่นคนเดียวหรือรับผิดชอบค่าลูกเอง = จ่ายเต็มจำนวน พร้อมแสดงยอดที่ต้องจ่ายให้เห็นก่อนกดบันทึก
  - **ใส่ชื่อเดิมซ้ำได้** — ถ้าใครออกค่าลูกแทนเพื่อน ให้ใส่ชื่อคนนั้นซ้ำในอีกช่องหนึ่ง เขาจะจ่ายตามจำนวนช่องที่มีชื่ออยู่ (เช่น 3 ช่อง หารคนละ 25 บ. คนที่อยู่ 2 ช่อง = 50 บ.) ฟอร์มจะสรุปให้เห็นก่อนบันทึก และยอดนี้จะตรงกันทั้งหน้าค้างชำระ หน้าจ่ายเงิน และข้อความใน LINE
  - การ์ด **สรุปเดือนนี้ (ชื่อเดือน)** จะเปลี่ยนตามเดือนที่กำลังดูอยู่บนปฏิทิน
  - **รวมชื่อที่ซ้ำกัน** — ผู้เล่นคนหนึ่งถูกจดคนละชื่อได้ง่ายมาก (สัปดาห์นี้ “น้องไอลีน” สัปดาห์หน้า “พี่ลีน”) ซึ่งจะกลายเป็นคนละคนในระบบ คือแยกประวัติและแยกยอดค้าง เมื่อกด **บันทึกเกม** แล้วเจอชื่อที่คล้ายกับคนที่มีอยู่แล้ว แอปจะถามก่อนบันทึกว่าจะ **รวมโดยใช้ชื่อเดิม**, **รวมแต่เปลี่ยนเป็นชื่อใหม่** (เปลี่ยนชื่อคนเดิมทั้งหมด ทุกเกมและการชำระเงินที่ผ่านมาจะเปลี่ยนตาม) หรือ **คนละคน** ถ้าตอบว่าคนละคน จะจำไว้และไม่ถามคู่นั้นอีก (จำไว้ในเครื่องที่ตอบเท่านั้น) การเทียบชื่อจะตัดคำนำหน้า **พี่ / น้อง / คุณ** ออกก่อนเสมอ แล้วเทียบเฉพาะชื่อจริง ๆ ดังนั้น “พี่บอล” กับ “พี่บิว” ถือเป็นคนละคนและจะไม่ถาม ส่วน “พี่บอล” กับ “น้องบอล” จะถาม — ถ้าเคยตั้งระบบไว้ก่อนหน้านี้แล้ว ต้องอัปเดต `Players.gs` กับ `Code.gs` แล้ว Deploy เวอร์ชันใหม่ ฝั่งเซิร์ฟเวอร์จึงจะรวมข้อมูลให้ได้
- **ค้นหา & จ่ายเงิน** — แสดงอันดับผู้ที่ยังค้างชำระ (เรียงจากยอดมากไปน้อย) พร้อมช่องค้นหา แตะชื่อเพื่อดูรายละเอียด: ช่วงวันที่ค้างชำระ จำนวนเกม จำนวนลูกขนไก่ รายการเกมแต่ละวัน ข้อมูลบัญชีรับชำระเงิน และปุ่มยืนยันว่าชำระแล้ว (รีเซ็ตยอดเป็น 0)
- **ตั้งค่า** — ต้องใส่รหัสผ่านก่อนเข้า (ค่าเริ่มต้น: `aerothaibadmintonclub2026`) ภายในมี 3 ส่วน: ราคาลูกขนไก่ต่อลูก (มีผลกับเกมใหม่เท่านั้น) รายละเอียดบัญชีรับชำระเงิน (พิมพ์อิสระ แสดงให้ผู้เล่นเห็นตอนกดชำระเงิน) และปุ่มส่งรายชื่อค้างชำระเข้ากลุ่ม LINE
- **แจ้งเตือนกลุ่ม LINE** — ทุก **วันจันทร์ 09:00** บอทส่งสรุปเข้ากลุ่ม 2 การ์ด: รายชื่อคนค้างชำระ 10 อันดับแรก (แต่ละคนมีปุ่ม "ชำระเงิน" ลิงก์เข้าแอป) และ **ประวัติการชำระเงิน 7 วันล่าสุด** (แตะชื่อเพื่อเปิดดูสลิป) และเรียกดูเองได้ตลอดด้วยการพิมพ์ `ยอดค้างชำระ` หรือ `ดูประวัติการจ่ายเงิน` ในกลุ่ม — การยืนยันชำระเงินและการแก้ไข/ลบเกม **ไม่ส่งข้อความเข้ากลุ่ม** เพื่อประหยัดโควตาข้อความ LINE (ดู [ตั้งค่า LINE Bot](#ตั้งค่า-line-bot-แจ้งเตือนกลุ่ม))

## ตั้งค่า LINE Bot (แจ้งเตือนกลุ่ม)

ฟีเจอร์นี้ใช้ Apps Script ตัวเดิมเป็นทั้ง webhook และตัวส่งข้อความ ไม่ต้องมีเซิร์ฟเวอร์เพิ่ม

> ถ้าเคยตั้งระบบไว้ก่อนหน้านี้แล้ว: หลังวางไฟล์ `Line.gs` และ `LineFlex.gs` ให้ **รัน `setupSheets` อีกครั้ง** เพื่อเพิ่มคอลัมน์ `source`, `line_user_id`, `method` และ `slip_url` ในชีต `Settlements` (ข้อมูลเดิมไม่หาย — ถ้าลืม ระบบจะเพิ่ม `slip_url` ให้เองตอนมีคนยืนยันชำระเงินครั้งแรก) แล้วรัน `setupSlips` และ `setupWeeklySummary` ตามข้อ 5–6 จากนั้นจึง Deploy เวอร์ชันใหม่

### 1. สร้าง Messaging API channel

1. ไปที่ [LINE Developers Console](https://developers.line.biz/console/) → สร้าง Provider → สร้าง channel แบบ **Messaging API**
2. แท็บ **Messaging API**:
   - **Channel access token (long-lived)** → กด Issue แล้วคัดลอกเก็บไว้
   - **Auto-reply messages** และ **Greeting messages** → ปิดทั้งคู่ (ไม่งั้นบอทจะตอบข้อความอัตโนมัติกวนในกลุ่ม)
   - **Allow bot to join group chats** → เปิด
3. เชิญบอทเข้ากลุ่ม LINE ของชมรม

### 2. ใส่ค่าใน Script Properties

ใน Apps Script editor → **Project Settings → Script Properties** → Add script property

| Property | ค่า |
| --- | --- |
| `LINE_CHANNEL_ACCESS_TOKEN` | token ที่ issue จากขั้นตอนที่ 1 |
| `LINE_WEBHOOK_TOKEN` | รหัสลับที่คิดขึ้นเอง (สุ่มยาว ๆ) ต้องตรงกับที่ใส่ใน webhook URL |
| `LINE_LIFF_URL` | URL ของแอปบน Vercel — **จำเป็น** เพราะปุ่ม "ชำระเงิน" ในการ์ดลิงก์กลับมาที่นี่ ถ้าไม่ใส่ การ์ดจะไม่มีปุ่ม |
| `LINE_TRIGGER_WORD` | (ไม่บังคับ) คำที่พิมพ์ในกลุ่มแล้วบอทจะส่งรายชื่อให้ ค่าเริ่มต้นคือ `ยอดค้างชำระ` — ใส่หลายคำได้โดยคั่นด้วย `,` เช่น `ยอดค้างชำระ, เช็คหนี้, ใครค้างบ้าง` |
| `LINE_HISTORY_TRIGGER_WORD` | (ไม่บังคับ) คำที่พิมพ์ในกลุ่มแล้วบอทจะส่งประวัติการชำระเงิน 7 วันล่าสุด ค่าเริ่มต้นคือ `ดูประวัติการจ่ายเงิน` — ใส่หลายคำได้โดยคั่นด้วย `,` |
| `LINE_SLIP_FOLDER_ID` | ไม่ต้องใส่ — ระบบสร้างโฟลเดอร์ Drive สำหรับสลิปแล้วจำ id ไว้เอง |

> เก็บไว้ใน Script Properties ไม่ใช่ชีต `Settings` เพราะ `getSettings()` เป็น API สาธารณะที่ใครก็เรียกได้ — ค่าอะไรที่อยู่ในชีตนั้นถือว่าอาจหลุดได้

### 3. ตั้ง Webhook URL

กลับไปที่แท็บ **Messaging API** → **Webhook URL** ใส่ URL ของ Web App พร้อมต่อท้ายด้วย `?lineToken=` และรหัสลับจากข้อ 2:

```
https://script.google.com/macros/s/XXXXX/exec?lineToken=<LINE_WEBHOOK_TOKEN>
```

แล้วเปิด **Use webhook**

> ⚠️ ปุ่ม **Verify** ของ LINE จะขึ้น error — เป็นเรื่องปกติ Apps Script ตอบ POST ด้วย redirect 302 ซึ่งตัว verify ไม่ตาม แต่ event จริงยังส่งถึงตามปกติ ให้ทดสอบด้วยการกดปุ่มในกลุ่มจริงแทน
>
> เหตุผลที่ต้องมี `lineToken`: Apps Script อ่าน HTTP header ไม่ได้ จึงตรวจ `X-Line-Signature` ของ LINE ไม่ได้ ใช้รหัสลับใน URL แทน — request ที่รหัสไม่ตรงจะถูกทิ้งโดยไม่ทำอะไรเลย

### 4. เชื่อมกลุ่ม

แค่ **เชิญบอทเข้ากลุ่ม** บอทจะทักในกลุ่มว่า "เชื่อมกลุ่มนี้เรียบร้อยแล้ว ✅" ทันที และจำ group id ไว้ใน `LINE_TARGET_IDS` เองอัตโนมัติ (ถ้าบอทเข้ากลุ่มอยู่ก่อนแล้ว พิมพ์อะไรก็ได้ในกลุ่ม 1 ครั้ง ก็จำได้เหมือนกัน) จากนั้นในแอปหน้า **ตั้งค่า** สถานะจะขึ้น "✅ พร้อมส่ง"

**เข้าได้หลายกลุ่มพร้อมกัน** — ทุกกลุ่มที่บอทอยู่จะได้รับสรุปรายสัปดาห์และรายชื่อที่ส่งจากหน้าตั้งค่า (แต่ละกลุ่มกินโควตาเท่าจำนวนสมาชิกในกลุ่มนั้น จึงควรให้บอทอยู่เฉพาะกลุ่มที่จำเป็น) การเพิ่มบอทเข้ากลุ่มใหม่ **ไม่ได้** ตัดกลุ่มเดิมออก ถ้าไม่อยากให้กลุ่มไหนได้รับแล้ว (เช่น กลุ่มที่ใช้ทดสอบ) ให้ **ลบบอทออกจากกลุ่มนั้น** บอทจะเลิกส่งให้เอง

> แชทส่วนตัวจะไม่ถูกนับเป็นปลายทาง ตราบใดที่บอทอยู่ในกลุ่มอย่างน้อย 1 กลุ่ม (ไม่งั้นรายชื่อของชมรมจะหลุดไปเข้าแชทส่วนตัวของสมาชิกที่ทักบอท)

> ทดสอบแบบไม่ต้องใช้กลุ่มก็ได้: แอดบอทเป็นเพื่อนแล้วทักแชทส่วนตัว 1 ครั้ง บอทจะใช้แชทนั้นเป็นปลายทางชั่วคราว พอพร้อมค่อยเพิ่มบอทเข้ากลุ่มจริง — กลุ่มจะมาแทนที่แชทส่วนตัวให้เอง

> อยากดูว่าตอนนี้บอทส่งเข้ากลุ่มไหนบ้าง: ใน Apps Script editor เลือกฟังก์ชัน **`debugListTargets`** แล้วกด Run (ถ้าต้องการตัดกลุ่มออกโดยไม่ลบบอท ใช้ `debugForgetTarget` แก้ id ในฟังก์ชันก่อนกด Run)

> **อัปเกรดจากเวอร์ชันเดิม:** ถ้าเดิมเคยตั้ง `LINE_TARGET_ID` ไว้ ระบบจะย้ายค่านั้นมาให้เองอัตโนมัติในการส่งครั้งแรก ไม่ต้องตั้งใหม่

### 5. เปิดสิทธิ์ Drive สำหรับเก็บสลิป (ห้ามข้าม)

ในหน้า Apps Script editor เลือกฟังก์ชัน **`setupSlips`** แล้วกด **Run** ครั้งเดียว จะมีหน้าต่างขอสิทธิ์ **Google Drive** ขึ้นมา ให้กด **Authorize**

ฟังก์ชันนี้จะสร้างโฟลเดอร์ `AeroThai Badminton — slips` สำหรับเก็บสลิป (ถ้าเคยตั้งไว้ก่อนหน้า จะเปลี่ยนชื่อโฟลเดอร์เดิมให้ และยกเลิก trigger ลบสลิปทุกชั่วโมงแบบเก่า)

> ⚠️ **ต้องรันก่อนใช้งานจริง** — หน้าเว็บแอปขอสิทธิ์เพิ่มเองไม่ได้ ถ้าข้ามขั้นตอนนี้ ตอนมีคนกดยืนยันชำระเงินแบบโอนครั้งแรกจะขึ้น error
> `คุณไม่ได้รับอนุญาตให้เรียกใช้ DriveApp.createFolder` และ **ยอดจะยังไม่ถูกตัด** (ระบบต้องเก็บสลิปได้ก่อนจึงบันทึก)
>
> ถ้าเจอ error นี้แล้ว: รัน `setupSlips` กด Authorize แล้ว **Deploy เวอร์ชันใหม่** จากนั้นให้กดยืนยันชำระเงินใหม่อีกครั้ง

### 6. ตั้งสรุปรายสัปดาห์ (ทุกวันจันทร์ 09:00)

ใน Apps Script editor เลือกฟังก์ชัน **`setupWeeklySummary`** แล้วกด **Run** ครั้งเดียว (ถ้ามีหน้าต่างขอสิทธิ์ให้กด Authorize) — ระบบจะตั้ง trigger ให้ส่งสรุปทุกวันจันทร์ 09:00 เวลาไทย (Google จะรันภายในประมาณ 15 นาทีหลัง 09:00) รันซ้ำได้ไม่ซ้อนกัน ในแอปหน้า **ตั้งค่า** จะขึ้น "🗓️ ส่งสรุปอัตโนมัติทุกวันจันทร์ 09:00"

- อยากลองส่งทันที: เลือกฟังก์ชัน **`sendWeeklyLineSummary`** แล้วกด Run
- ถ้าวันจันทร์ไหนส่งไม่สำเร็จ (เช่น โควตาหมด) Google จะส่งอีเมลแจ้งเจ้าของสคริปต์

**โควตาข้อความ:** LINE นับข้อความ push เป็น "จำนวนสมาชิกในกลุ่ม × จำนวนครั้งที่ส่ง" (การ์ด 2 ใบในการส่งครั้งเดียวนับเป็นครั้งเดียว) ส่วนการตอบกลับเมื่อมีคนพิมพ์คำสั่งในกลุ่ม **ไม่นับโควตา**

| สิ่งที่ส่ง | ใช้โควตา (กลุ่ม 50 คน) |
| --- | --- |
| สรุปรายสัปดาห์ (4–5 ครั้ง/เดือน) | 200–250 ข้อความ/เดือน |
| กดปุ่มส่งรายชื่อจากหน้าตั้งค่า | 50 ข้อความ/ครั้ง |
| พิมพ์ `ยอดค้างชำระ` / `ดูประวัติการจ่ายเงิน` | 0 |
| ยืนยันชำระเงิน / แก้ไข-ลบเกม | 0 (ไม่ส่งข้อความ) |

### 7. วิธีใช้งาน

1. เรียกรายชื่อค้างชำระได้ 3 ทาง — รอสรุป **วันจันทร์ 09:00**, พิมพ์ **`ยอดค้างชำระ`** ในกลุ่ม LINE (ใครก็ได้ ไม่ต้องเปิดแอป ตั้งคำอื่นเพิ่มได้ที่ `LINE_TRIGGER_WORD`) หรือหน้า **ตั้งค่า** → กด **ส่งรายชื่อค้างชำระเข้ากลุ่ม LINE**
2. ในกลุ่มจะเห็นรายชื่อ **10 อันดับแรก** พร้อมยอด และปุ่ม **ชำระเงิน** ของแต่ละคน (ถ้าเกิน 10 คนจะขึ้น "… และอีก N คน" พร้อมปุ่มดูทั้งหมด)
3. กด **ชำระเงิน** → เปิดแอปที่หน้า **ค้นหา & ชำระเงิน** พร้อมใส่ชื่อเล่นของคนนั้นในช่อง "ค้นหาชื่อเล่น หรือ กอง" ให้เลย รายชื่อจะถูกกรองเหลือเฉพาะคนนั้น
4. กด **ยืนยันชำระเงิน** ที่ชื่อตัวเอง แล้วเลือก **วิธีชำระเงิน**:
   - **🏦 โอนเงิน** (ค่าเริ่มต้น) — โอนแล้ว **แนบสลิป** (บังคับ) → กด **ยืนยันว่าชำระแล้ว**
   - **💵 จ่ายเงินสด** — ไม่ต้องแนบสลิป กด **ยืนยันว่าชำระแล้ว** ได้เลย
5. ระบบเก็บสลิปไว้ใน Google Drive แล้วบันทึกลงชีต `Settlements` (คอลัมน์ `method` = `transfer` / `cash` และ `slip_url` = ลิงก์สลิป) — **ไม่มีข้อความส่งเข้ากลุ่ม** การจ่ายเงินจะไปโผล่ในสรุปวันจันทร์ถัดไปแทน
6. ดูว่าใครจ่ายแล้วบ้าง: พิมพ์ **`ดูประวัติการจ่ายเงิน`** ในกลุ่ม (หรือรอสรุปวันจันทร์) บอทจะตอบการ์ด **ประวัติการชำระเงิน 7 วันล่าสุด** เรียงจากล่าสุด บอกชื่อ วันเวลา วิธีจ่าย (🏦 โอน / 💵 เงินสด) และยอด — **แตะที่ชื่อ** (ตัวสีน้ำเงินขีดเส้นใต้) เพื่อเปิดดูสลิปใน Google Drive (จ่ายเงินสด และรายการที่บันทึกก่อนมีฟีเจอร์นี้ จะไม่มีสลิปให้กด)

การตัดยอดทั้งหมดเกิดขึ้นในแอป ไม่ได้เกิดในแชท — บอททำหน้าที่เป็นกระดานประกาศอย่างเดียว จึงไม่มีปุ่มที่ตัดยอดได้จากในกลุ่ม การแก้ไข/ลบเกมก็ไม่แจ้งเข้ากลุ่มแล้ว ยอดที่เปลี่ยนจะเห็นในรายชื่อค้างชำระครั้งถัดไป

**เรื่องสลิป:** สลิปถูกเก็บถาวรในโฟลเดอร์ Drive `AeroThai Badminton — slips` แบบ **"ใครมีลิงก์ก็ดูได้"** เพื่อให้แตะดูจาก LINE ได้โดยไม่ต้องล็อกอิน Google — ลิงก์ถูกส่งเฉพาะในกลุ่มของชมรม แต่ใครที่ได้ลิงก์ต่อไปก็เปิดดูได้ ถ้าต้องการลบสลิปเก่า ลบไฟล์ในโฟลเดอร์นั้นได้เลย (ลิงก์ในการ์ดจะเปิดไม่ขึ้นเท่านั้น ยอดไม่กระทบ)

> หมายเหตุ: ข้อความ LINE แก้ไขย้อนหลังไม่ได้ การ์ดเก่าจึงยังค้างอยู่ในแชท แต่ละใบมีเวลากำกับว่า "ข้อมูล ณ ..." ถ้ากดปุ่มจากการ์ดเก่าของคนที่จ่ายไปแล้ว แอปจะบอกว่า "ไม่มียอดค้างชำระแล้ว" แทนการเปิดหน้าจ่ายเงินเปล่า ๆ

### การเปลี่ยนรหัสผ่านหน้าตั้งค่า

รหัสผ่านเก็บอยู่ในชีต `Settings` แถว key = `settings_password` แก้ค่าในช่อง value ได้โดยตรงจาก Google Sheet

แอปนี้เปิดให้ทุกคนที่มีลิงก์ใช้งานได้โดยไม่ต้องล็อกอิน (ยกเว้นหน้าตั้งค่าที่มีรหัสผ่าน) จึงควรแชร์ลิงก์เฉพาะภายในกลุ่มที่ไว้ใจกัน
